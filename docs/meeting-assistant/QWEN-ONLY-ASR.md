# Qwen-only ASR migration

## Decision

The user requested replacement of **all** original speech-recognition routes, not another opt-in provider. After inspection, they explicitly chose removal of the old implementations and build dependencies. The supported choices are **Qwen3-ASR 1.7B / 0.6B**, both using the existing decoder-INT8, encoder/prefill-F32 worker. 1.7B remains the default. This supersedes earlier instructions to retain Whisper/Parakeet/default ASR. It does not change summary providers, authentication, source-preserving capture/VAD, gain, language policy or recording format.

## Implementation

- Retired Whisper/Parakeet engines, adapters, registered commands, model managers, automatic onboarding downloads, unused legacy capture/STT backups and direct dependencies are removed. ONNX remains for the existing Silero VAD; it is not a leftover Parakeet requirement. Existing database columns such as `whisperModel` are retained for schema/data compatibility, not used as ASR routes.
- Live recording, file import and saved-audio retranscription all use `QwenProvider`. No fallback to another model/provider. Unknown Qwen IDs fail closed. Retired provider selections migrate to the Qwen 1.7B default with one conditional SQL update; a concurrent explicit Qwen selection is never overwritten. Keys, downloaded models, audio, transcripts and minutes are not deleted.
- Both models have distinct prepared settings and writable installation directories. The existing 1.7B `qwen-asr.json` remains compatible; small uses `qwen-asr-0.6b.json`. Installed model discovery can return either/both; batch dialogs do not silently substitute the other installed model when the configured choice is missing.
- Setup accepts a catalog model ID, never caller-supplied URLs. Each model has an independently pinned official revision, file sizes and SHA256 manifest. Explicit unchecked download consent remains required. Per-job model identity is checked before applying the result, including after remount/reload. Neither mounting nor polling selects a model.
- Small cache layout is 599,834,624 bytes versus 1,724,760,064 bytes for 1.7B. The existing pinned 1.7B payload check remains. Small setup regenerates its cache in private staging from checksum-verified official weights and compares any existing cache to that fresh result; it never trusts an unpinned existing cache or overwrites a mismatching one. CPU/memory cost of this fresh regeneration is not hidden.
- The worker identifies the requested model from its config before `ready` and supports both decoder widths (1024/2048, 28 layers). The adapter retains the original two-argument worker CLI so existing float32/full-input 1.7B workers remain usable, and rejects a mismatching model handshake. The new worker's optional explicit `--model` without installed weights permits only a runtime startup/shutdown probe (`model_loaded:false`); missing config without that explicit identity fails. Actual inference additionally checks tensor dimensions against the config. A ready handshake alone is not a model-integrity or speech-quality claim.
- Batch jobs own an independent adapter and freeze their language/model before copying/modifying data. A shared lease excludes simultaneous import/retranscription and recording startup. Setup start is serialized with recording/batch startup, and active setup also blocks ASR startup and model/path changes until initialization/cancellation finishes. Cancellation interrupts in-flight inference, dropping the request-owned worker and temporary float WAV. Failed audio is not retried. A batch worker cannot unload a live worker.
- Retranscription retains the database transaction and original metadata fields; verifies the saved meeting/folder binding; inference failure, cancellation and empty recognition do not delete existing text. Imported/reprocessed mixed files retain unknown capture origin. Existing transcripts and canonical minutes are not automatically reprocessed.
- Onboarding is Qwen-only and does not require a local summary model. The existing database initialization/legacy import is retained. Unsupported systems display an error rather than exposing the retired ASRs. Packaged automatic setup remains Linux x86_64 / Windows x64; macOS Qwen support is not newly implemented.
- Nix app source closure includes both manifests. The optional Home Manager preprepared-path configuration has `qwenModelSize = "1.7b" | "0.6b"`; it does not select/download a model. `nix run .#prepare-qwen-model-0_6b -- /absolute/model/directory` prepares small weights explicitly, independently of ordinary consent-based app setup. Home Manager backups are per settings file. Windows manual preparation accepts `-ModelSize 0.6B` and retains the old positional model-directory argument; no Home Manager activation or Windows release build was executed.

### Retained failures and corrections

- First TypeScript check found two comparisons to the now-retired provider and a test missing the new model prop; corrected the consumers/test contract.
- Node initially passed 42/43: the Windows source guard still expected the obsolete second `qwen_init` call. It now checks actual candidate validation before persistence, not bypassed validation; all 46 tests pass.
- Initial offline native checks were blocked by absent Git dependencies / crates.io `jni` metadata in the cold cache. The unpinned channel shell tried an unnecessary second toolchain download; owned attempts were stopped and the flake-pinned shell used. An exploratory Nix cargo-vendor fetch was interrupted, not counted as a package build. Public index metadata and **checksum-verified pinned crate archives** populated the build cache without credentials/app data. Cargo pruned nine obsolete packages; retained package versions, pnpm lock and standalone worker lock are unchanged. The first native check then found the missing helper sidecar; an existing helper was copied for debug checks. The first standalone worker link lacked `-L` for BLAS in the developer shell; fixed test-shell linking/RPATH using the already LP64 library. All failures remain in the logs.
- GUI harness r1 had an incorrectly quoted CSS selector; r2 counted WebKit HSTS as an app database; r3 assumed Settings was an anchor rather than the actual sidebar button; r4 clicked an animating/stale Radix control. Fixed only harness selection/identification, retaining the intended model/storage checks. Scope to the open dialog and a real keyboard event yields passing full runs. Synthetic profiles/logs remain outside Git.

No real microphone/desktop capture, physical speaker playback, user audio/transcript read, cloud inference, auth changes, ordinary-profile migration execution, visible app replacement or release was performed. Real 0.6B speech inference, full new-model HTTPS download/initialization, Windows/clean-host packaging, natural meetings and long-file acceptance remain unverified. Existing short-word/noise recognition failures are not fixed by offering another model. Older upstream release/portability recipes are not distribution acceptance for the Qwen-only fork; do not publish from them without a separate runtime/packaging audit.
